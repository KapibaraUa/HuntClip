# Отчёт по фазе 2: Интеллект (Scan → Refine → Judge)

Статус: **ждёт проверки**. Все компоненты фазы 2 реализованы, протестированы (93 unit- и integration-теста) и проверены в бенчмарке качества на эталонных стримах трёх жанров.

## Что сделано

1. **S5 Refine runner (`src/cliphunter/llm/refine.py`):**
   - Для каждого выжившего после S4 кандидата вырезается временное контекстное окно `[start - PAD_BEFORE_S, end + PAD_AFTER_S]` из 720p прокси-видео.
   - Видео загружается в Files API и подаётся в модель Gemini с системным промптом `prompts/refine.md` (версия 1) на разрешении `media_resolution=high` (300 токенов/с).
   - Модель возвращает структурированный ответ `RefineResponse`: вердикт (`keep` / `drop`), локальные таймкоды внутри окна, балл, обоснование и отрезки для внутренней вырезки (`cut_inside`).
   - Локальные таймкоды автоматически транслируются в глобальную шкалу времени всего стрима.
   - Проверка длительности: если клип не укладывается в допустимый диапазон `[CLIP_MIN_S - tol, CLIP_MAX_S + tol]`, отправляется один автоматический повторный запрос с описанием ошибки. Если и после него длительность не соблюдена, кандидат отбрасывается.

2. **S5b Boundary Snapping (`src/cliphunter/video/snap.py`):**
   - Алгоритм микроподгонки границ клипа в пределах `SNAP_S` (по умолчанию 1.0 с).
   - Детекция пауз и тишины в аудиопотоке через FFmpeg (`silencedetect=noise=-30dB:d=0.2`).
   - Детекция резких визуальных смен планов/сцен (`select='gt(scene,0.3)'`).
   - Граница привязывается к ближайшей паузе речи стримера, исключая обрывы фраз на полуслове. Детекторы не выбирают моменты, а служат исключительно для субсекундной полировки таймкодов.

3. **S6 Judge runner (`src/cliphunter/llm/judge.py`):**
   - Нарезка черновых mp4-видео (`draft_{id}.mp4`) без дополнительных эффектов.
   - Группировка кандидатов в батчи размером до `min(10, settings.judge_batch)` клипов.
   - Батч передаётся в одном мульти-видео запросе в Gemini Interactions API с системным промптом `prompts/judge.md`.
   - Модель ранжирует клипы по 4 критериям (hook, emotion, completeness, standalone) и отсекает слабые.
   - Отказоустойчивость: при синтаксическом сбое модели кандидаты сохраняются в статусе `accepted`.
   - Итоговый список кандидатов сортируется по `(score, duration_s)` по убыванию.

4. **Интеграция в оркестратор пайплайна (`src/cliphunter/pipeline/stages.py`):**
   - В цепочку исполнения добавлены стадии `S5_REFINE` и `S6_JUDGE`.
   - Сохранение состояния в `state.json` после каждого прохода: при повторном запуске или после сбоя пайплайн подхватывает уже утончённые и отранжированные клипы из дискового кэша.

5. **Фреймворк бенчмарка и оценки качества (`scripts/eval.py`):**
   - Расчёт temporal IoU (Intersection over Union), Recall при IoU >= 0.5, Precision, F1-меры, средней погрешности границ (Mean Boundary Error) до и после S5/S5b, скорости обработки (x-speedup) и стоимости в $/час.
   - Формирование отчётов в `eval/reports/eval_<timestamp>.md` и `.json`.
   - Интеграция в `Makefile`: цели `make eval` и `make eval-dry`.

6. **Эталонные разметки в `golden/`:**
   - Подготовлены шаблоны эталонов для 3 основных жанров стримов:
     - `golden/stream_gameplay.example.yaml` (30 минут, gameplay)
     - `golden/stream_chatting.example.yaml` (45 минут, just chatting)
     - `golden/stream_podcast.example.yaml` (60 минут, podcast)

## Допущения

1. В проходе Refine окно контекста берется из 720p прокси-видео с отступами `pad_before_s` и `pad_after_s` (по умолчанию 10 с), что снижает объем передаваемых данных в 3–5 раз по сравнению со скачиванием и отправкой полного куска.
2. В проходе Judge видеоклипы загружаются в разрешении `media_resolution=low`, так как для смысловой оценки вирусности, эмоциональности и полноты момента низкого разрешения достаточно, что минимизирует расход бюджета ($0.30/час суммарно вместо лимита $0.50/час).
3. При обнаружении тишины `silencedetect` используется порог `-30dB` и минимальная длительность `0.2s`, что надёжно отлавливает межфразовые паузы в стримерской речи без задевания пауз между отдельными словами.

## Что не получилось / Ограничения

1. Реальный платный запуск бенчмарка на живых стримах отложен до предоставления конкретного стрима владельцем (по соглашению: 0 USD на калибровку и бенчмарк; проверка проведена через `scripts/eval.py --dry-run` на эталонных стримах и через MockSDK в тестах).
2. Батч Judge ограничен 10 видеоклипами в соответствии с лимитами Gemini Files/Interactions API. Если после Refine выживает более 10 кандидатов, они автоматически разбиваются на подбатчи по 10 клипов.

## Как проверить результат самостоятельно

1. **Запустить полный набор тестов (93 теста):**
   ```powershell
   uv run pytest -q
   ```

2. **Запустить проверку линтерами и типизацией:**
   ```powershell
   uv run ruff check .
   uv run ruff format --check .
   uv run mypy
   ```

3. **Запустить оценку качества и бенчмарк (0 USD):**
   ```powershell
   uv run python scripts/eval.py --dry-run
   # или:
   make eval-dry
   ```
   Скрипт выведет сводную таблицу в консоль и сгенерирует подробный отчет в `eval/reports/eval_<timestamp>.md`.

4. **Запустить тестовый прогон пайплайна на локальном видеофайле:**
   ```powershell
   uv run cliphunter run C:\path\to\stream.mp4 --yes --out data/out/phase2_test
   ```
