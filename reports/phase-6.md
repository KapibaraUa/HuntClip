# Отчёт по фазе 6: Удобства

*Дата: 21.10.2026 · Проект: ClipHunter · Статус: Реализована и готова к проверке*

## 1. Цель фазы
Реализация сервисных удобств для повседневной работы нарезчиков и стримеров согласно техническому заданию (`docs/plan.md`, раздел 11, Фаза 6):
1. **Telegram-бот на базе `aiogram 3` (`src/cliphunter/bot/telegram.py`):**
   - Приём ссылок на YouTube/Twitch и видеофайлов напрямую в чат.
   - Расчёт токеноёмкости и оценка стоимости по модели Gemini перед запуском.
   - Интерактивное подтверждение запуска через inline-кнопки.
   - Стриминг прогресса по этапам пайплайна (S0 Ingest → S1 Proxy → S2 Chunk → S3 Scan → S4 Merge → S5 Refine → S6 Judge → S7 Cut).
   - Отправка готовых смонтированных `.mp4` клипов в чат Telegram (лимит 50 МБ) или выдача пути к файлу при превышении лимита.
   - Авторизация доступа по белому списку `TELEGRAM_ALLOWED_IDS`.
   - Команды `/start`, `/help`, `/jobs`, `/cancel <id>`, `/profiles` (с inline-выбором активного пресета).
2. **Запись и прогрессивный анализ идущих стримов (`src/cliphunter/ingest/live.py`, требование F10):**
   - Получение прямого медиа-потока HLS/m3u8 через `yt-dlp -g` для YouTube Live, Twitch, Kick и веб-трансляций.
   - Сегментация на лету через FFmpeg (`-f segment -segment_time {chunk_s}`).
   - Мониторинг завершения сегментов и непрерывный запуск фоновых задач обработки по каждому готовому сегменту.
   - Кандидаты и клипы появляются в БД, SSE-стриме и ревью-интерфейсе прямо во время стрима.
3. **Поддержка Twitch и произвольных веб-источников (требование F3):**
   - Распознавание каналов, VOD и клипов `twitch.tv` и `clips.twitch.tv`.
   - Корректная обработка live-потоков с неизвестной длительностью (`duration_s = 0.0`).
4. **Пакетная обработка очередей ссылок (`batch`):**
   - Эндпоинт `POST /api/jobs/batch` для постановки пачки видео в очередь.
   - Команда CLI `cliphunter batch [targets...] [--file links.txt] [--profile ...] [--yes] [--capcut]`.
5. **Редактор профилей стримеров в Web UI:**
   - Модальное окно «Редактор профилей» (`#modal-profiles`) с сайдбаром существующих пресетов (`default`, `evelone2004`, `gaming_action`, `just_chatting`, пользовательские) и кнопкой «+ Новый».
   - Интерактивная настройка: имя, язык, игра/категория, мин/макс длительность клипов, нормализованные координаты вебкамеры (`facecam_rect`: X, Y, W, H) и персональная промпт-надстройка для Gemini.
   - Сохранение через `PUT /api/profiles/{name}` и мгновенное обновление выпадающего списка на главной странице.

## 2. Что реализовано

### 2.1. Telegram-бот (`src/cliphunter/bot/telegram.py`, `src/cliphunter/bot/__init__.py`)
- **Архитектура:** Асинхронный бот на `aiogram 3.31.0` (`Dispatcher`, `Router`, `Bot`).
- **Контроль доступа:** Функция `is_user_allowed()` проверяет `message.from_user.id` по списку `settings.telegram_allowed_ids`. Если список пуст (локальная разработка/тесты), разрешает доступ; в боевом режиме вежливо блокирует и выводит `user_id`.
- **Оценка стоимости:** При отправке текстового сообщения с ссылкой бот выполняет пробинг источника (`probe_source`), рассчитывает стоимость (`estimate_video_cost`) и выводит карточку видео с кнопками `[🚀 Запустить ($X.XX)]` и `[❌ Отмена]`.
- **Загрузка видео:** Поддерживает отправку видеофайлов (mp4, mkv, mov, webm). Файл скачивается через `bot.download_file()`, сохраняется в `data/uploads/`, после чего предлагается подтверждение запуска.
- **Стриминг прогресса:** Функция `track_job_and_deliver()` непрерывно отслеживает состояние задачи в БД и редактирует сообщение бота с троттлингом (не чаще раза в 1.5 с).
- **Доставка готовых клипов:** По завершении задачи бот запрашивает клипы из БД:
  - Клипы до 50 МБ отправляются видеосообщениями в чат через `bot.send_video(FSInputFile(clip_path))` с метаданными (название, оценка Gemini, таймкод, хронометраж, макет).
  - Клипы свыше 50 МБ (лимит Bot API) сопровождаются информационным сообщением с указанием локального пути на сервере.
- **Команды и управление:**
  - `/start` — приветствие и быстрый старт.
  - `/help` — форматы, ограничения и лимиты.
  - `/jobs` — последние 10 задач, их статус, этап и затраты.
  - `/cancel <job_id>` — отмена активной задачи через `task_manager.cancel_job()`.
  - `/profiles` — просмотр и переключение активного профиля для текущего пользователя через inline-кнопки.

### 2.2. Запись и анализ идущих стримов (`src/cliphunter/ingest/live.py`)
- **`extract_stream_direct_url(url)`:** Автоматически извлекает прямой поток трансляции (HLS `.m3u8` / HTTP stream) через `yt-dlp -g`.
- **`LiveStreamRecorder`:** Запускает асинхронный процесс FFmpeg с сегментным муксером (`-f segment -segment_time {chunk_s} -reset_timestamps 1 {output_dir}/chunk_%04d.mp4`) и фоновым наблюдателем `_watch_segments()`. При появлении следующего файла `chunk_{i+1}.mp4` предыдущий сегмент `chunk_{i}.mp4` гарантированно считается закрытым и готовым к обработке.
- **`LiveStreamSession`:** Высокоуровневый координатор сессии трансляции. Для каждого готового сегмента создаёт запись источника (`probe_file`), задачу `Job` и запускает её в фоновом менеджере `task_manager.start_job()`. Нарезка и анализ идут параллельно самой трансляции.

### 2.3. Twitch и веб-источники (`src/cliphunter/ingest/probe.py`)
- Добавлен детектор Twitch: `_TWITCH_REGEX` распознает `twitch.tv/...` и `clips.twitch.tv/...`.
- Добавлена функция `is_live_stream(info)`: распознает флаги `is_live` и `live_status == "is_live"`.
- Пробинг живых стримов корректно обрабатывает отсутствие длительности (`dur = 0.0`), предотвращая сбои при постановке задачи.

### 2.4. Пакетная очередь (`POST /api/jobs/batch` и `cliphunter batch`)
- **API:** Эндпоинт `POST /api/jobs/batch` принимает `{ urls: [...], profile_id, max_cost_usd, auto_yes }`, валидирует непустой список, последовательно регистрирует источники, создаёт задачи в БД и запускает их параллельно через `task_manager`.
- **CLI:** Команда `cliphunter batch` принимает ссылки аргументами командной строки или через `--file links.txt` (поддерживает текстовые файлы со списком URL и комментариями `#`), прогоняет через `PipelineRunner` с формированием итогового отчёта успехов/ошибок.

### 2.5. Редактор профилей стримеров в Web UI (`index.html`, `app.js`, `style.css`)
- В верхнюю панель навигации добавлена кнопка **«⚙️ Профили»**.
- Модальное окно `modal-profiles` содержит сайдбар со всеми пресетами из базы данных и кнопку «+ Новый».
- Форма редактирования позволяет интерактивно менять и сохранять:
  - Имя профиля (заблокировано для базового `default`, редактируемо для остальных).
  - Язык стрима (`ru`, `en`).
  - Категорию / игру (`Just Chatting`, `CS2`, `Dota 2`).
  - Мин. и макс. длину клипа (сек).
  - Четыре нормализованные координаты вебкамеры (`facecam_rect`: X, Y, W, H от 0.0 до 1.0).
  - Персональную промпт-надстройку для подсказок Gemini.
- Сохранение выполняется по нажатию кнопки через API `PUT /api/profiles/{name}` с всплывающим уведомлением (toast) и мгновенным обновлением селектора профилей на экране создания задачи.

### 2.6. CLI команды (`src/cliphunter/cli.py`)
- `cliphunter bot [--token TOKEN]` — запуск Telegram-бота.
- `cliphunter live <url> [--chunk-s 2700] [--profile default] [--yes] [--max-chunks N]` — сессия записи и прогрессивной нарезки стрима.
- `cliphunter batch [targets...] [--file links.txt] [--profile ...] [--yes] [--capcut]` — пакетная обработка очередей видео.
