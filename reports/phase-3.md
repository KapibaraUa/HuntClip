# Отчёт по фазе 3: Сервис и ревью

*Дата: 21.10.2026 · Проект: ClipHunter · Статус: Реализована и готова к проверке*

## 1. Цель фазы
Реализация сервисной архитектуры приложения ClipHunter согласно разделам 6, 7, 11 и 14 технического задания (`docs/plan.md`):
- База данных и схема хранения сущностей (Postgres / SQLite async + Alembic).
- FastAPI backend со всеми эндпоинтами из раздела 11.
- Асинхронный менеджер фоновых задач с поддержкой паузы на ручное ревью (`awaiting_review`) и отправкой событий через Server-Sent Events (SSE).
- Потоковая отдача медиа с поддержкой заголовка `Range` (HTTP 206 Partial Content) для мгновенной покадровой перемотки в плеере.
- Полнофункциональный веб-интерфейс нарезчика (4 экрана из раздела 11: Новая задача, Прогресс, Ревью с подгонкой границ ±0.1 с и ручным добавлением, Результаты с предпросмотром и скачиванием).
- CLI-команда запуска сервиса: `cliphunter serve`.

## 2. Что реализовано

### 2.1. База данных и ORM (`src/cliphunter/db/`)
- Модели данных SQLAlchemy 2.0 async (`src/cliphunter/db/models.py`):
  - `SourceORM` (источники: YouTube URL, локальные файлы, хэш sha256, длительность, метаданные).
  - `JobORM` (задачи нарезки, профиль, параметры, этапы, статус, текущий расход USD, пути).
  - `ChunkORM` (куски стрима, токены, статусы).
  - `CandidateORM` (найденные клипы, границы `start_s`/`end_s`, категория, балл 1-10, статус, свидетельства `why_viral`, `visual_evidence`, `audio_evidence`, варианты заголовков).
  - `ClipORM` (смонтированные клипы, путь к MP4, layout, манифест).
  - `ApiCallORM` (журнал всех платных вызовов модели Gemini: токены in/out, latency ms, cost USD, cache_hit).
  - `ProfileORM` (профили стримеров, координаты областей фейскама и геймплея, мин/макс длительности).
- Асинхронный репозиторий CRUD-операций (`src/cliphunter/db/repo.py`).
- Миграции Alembic: `alembic/versions/5b2fe2a08d89_initial_schema.py` для развертывания в PostgreSQL и SQLite.

### 2.2. FastAPI Backend и API (`src/cliphunter/api/`)
Реализован полный набор эндпоинтов по разделу 11:
- `POST /api/uploads` — загрузка видеофайлов по частям (multipart) с подсчётом sha256 и проверкой через `ffprobe`.
- `POST /api/jobs` — создание задачи нарезки, валидация профиля и лимитов, запуск фонового пайплайна.
- `GET /api/jobs` и `GET /api/jobs/{id}` — список задач и детальная информация.
- `GET /api/jobs/{id}/events` — стриминг этапов и расходов в реальном времени по SSE (`JobEventBroadcaster`).
- `POST /api/jobs/{id}/cancel` и `POST /api/jobs/{id}/retry-stage` — управление жизненным циклом задачи.
- `POST /api/jobs/estimate` — предварительная оценка длительности, токенов и стоимости стрима до старта.
- `GET /api/jobs/{id}/candidates` — получение списка найденных кандидатов.
- `PATCH /api/candidates/{id}` — интерактивная правка границ начала и конца (с шагом до 0.1 с), заголовка и статуса (`accepted`/`rejected`).
- `POST /api/jobs/{id}/candidates` — ручное добавление момента нарезчиком с присвоением `status="accepted"` и `source_pass="manual"`.
- `POST /api/jobs/{id}/render` — запуск нарезки и монтажа принятых кандидатов в итоговые MP4.
- `GET /api/jobs/{id}/clips` и `GET /api/clips/{id}/download` — выдача готовых MP4 файлов с корректными HTTP-заголовками `Content-Disposition`.
- `GET /api/jobs/{id}/usage` — агрегированный отчёт о токенах, вызовах, cache hit rate и затратах по каждому этапу пайплайна.
- `GET /api/profiles` и `PUT /api/profiles/{name}` — управление пресетами стримеров.
- `GET /api/media/proxy/{id}` и `GET /api/media/clips/{id}` — потоковая отдача видео с поддержкой HTTP 206 Range requests.

### 2.3. Фоновый воркер и пайплайн (`src/cliphunter/worker/tasks.py`)
- Асинхронный менеджер `JobTaskManager`.
- Пайплайн последовательно проходит этапы S0 (Ingest) → S1 (Proxy 720p) → S2 (Plan) → S3 (Scan) → S4 (Merge) → S5 (Refine) → S5b (Snap) → S6 (Judge).
- **Шлюз ручного ревью:** по завершении S6 задача переходит в статус `awaiting_review`, сохраняет кандидатов в базу данных и отправляет оповещение по SSE в браузер.
- Если в конфиге включен флаг `AUTO_RENDER=true`, пайплайн автоматически рендерит кандидатов без остановки.
- Единый механизм монтажа: моменты от ИИ и моменты, добавленные пользователем вручную, рендерятся одной функцией FFmpeg с покадровой точностью и аудио-затуханиями.

### 2.4. Веб-интерфейс SPA (`src/cliphunter/web/`)
Создан современный тёмный интерфейс с акцентами (индиго/фиолетовый, изумрудный, янтарь) и шрифтами Inter и JetBrains Mono:
1. **Экран 1: Новая задача.**
   - Переключение между вводом YouTube URL и Drag-and-Drop загрузкой файла с визуальным прогресс-баром.
   - Выбор профиля стримера (`default`, `evelone2004`, `gaming_action`, `just_chatting`) с подсказками.
   - Ползунки длительности клипов и лимит бюджета USD.
   - Кнопка «Оценить» с предварительным расчётом длительности и стоимости.
2. **Экран 2: Ход задачи.**
   - Интерактивная шкала этапов (степпер) с пульсирующей анимацией текущего этапа и отметками пройденных.
   - Капсулы текущего расхода USD и числа найденных кандидатов.
   - Терминал журнала событий реального времени (SSE-лог).
   - Кнопки отмены и возобновления задачи.
3. **Экран 3: Ревью клипов.**
   - HTML5 видеоплеер с поддержкой перемотки и потокового HTTP 206 воспроизведения 720p прокси.
   - Интерактивный скраббер с визуальным отображением диапазонов всех кандидатов на таймлайне.
   - Кнопки перемотки (±5с, ±1с, ±0.1с).
   - Карточки кандидатов с оценкой вирусности (1-10), категорией, аргументами модели (`why_viral`, `visual_evidence`, `audio_evidence`).
   - Кнопки точной подгонки границ: **`-1s`, `-0.1s`, `+0.1s`, `+1s`** для начала и конца каждого клипа.
   - Модальное окно добавления момента вручную (с фиксацией текущего времени плеера).
   - Выбор формата монтажа (`original`, `blur_fit_9x16`, `facecam_top_game_bottom_9x16`) и кнопка «Запустить рендер».
4. **Экран 4: Результаты.**
   - Сетка готовых клипов со встроенным видеопроигрывателем.
   - Кнопка прямого скачивания MP4.
   - Кнопка копирования заголовка клипа в буфер обмена.
   - Модальное окно полного отчёта по токенам и вызовам Gemini API (`/api/jobs/{id}/usage`) с разбивкой по этапам и логом запросов.

## 4. Принятые допущения
Зафиксированы в `docs/DECISIONS.md` (пп. 36–42):
- База данных по умолчанию SQLite (`sqlite+aiosqlite:///data/cliphunter.db`) для обеспечения 100% автономной работы на Windows без обязательного демона Docker. Для продакшена доступен PostgreSQL через `.env`.
- Поддержка HTTP 206 Partial Content стриминга через генератор блоков по 1 МБ с чтением диапазона `Range`.
- Границы клипов округляются до 0.1 секунды.

## 5. Как запустить и проверить вручную

1. Запусти сервер приложения:
   ```powershell
   uv run cliphunter serve
   ```
2. Открой в браузере: **`http://127.0.0.1:8000`**
3. Проверь полный цикл:
   - Введи ссылку на YouTube или перетащи локальный видеофайл.
   - Нажми «Оценить» — отобразится предварительная стоимость.
   - Нажми «Запустить поиск клипов» — перейди на экран 2 и наблюдай за этапами по SSE.
   - По завершении откроется экран 3 (Ревью): видео воспроизводится и перематывается, границы двигаются кнопками ±0.1с, добавь момент вручную.
   - Нажми «Запустить рендер клипов» — откроется экран 4 со скачиванием готовых клипов и отчётом о токенах.
