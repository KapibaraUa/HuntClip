# Известные ограничения и особенности эксплуатации (LIMITATIONS)

Документ фиксирует архитектурные, платформенные и сторонние ограничения системы **ClipHunter**, а также предусмотренные в коде защитные механизмы.

---

## 1. Модель ИИ и Gemini Interactions API

1. **Квоты и лимиты запросов (HTTP 429 / 5xx):**
   - На бесплатном тарифе Google AI Studio действуют жёсткие лимиты по числу запросов в минуту (RPM), числу токенов в минуту (TPM) и суммарной длительности анализируемых YouTube-видео в сутки. Для регулярной обработки стримов от 2 часов необходим платный тариф (Pay-as-you-go).
   - При получении `429 Too Many Requests` или `5xx` клиент `GeminiVideoClient` выполняет экспоненциальный backoff с джиттером, но при исчерпании дневной квоты задача перейдёт в статус `failed` с сохранением прогресса в `state.json` (её можно продолжить позже с того же куска).
2. **Срок жизни файлов в Gemini Files API:**
   - Загруженные видеофрагменты в облаке Google хранятся ограниченное время (около 48 часов), после чего автоматически удаляются.
   - На `file_uri` нельзя опираться как на долговременное хранилище: поэтому все ответы ИИ кэшируются локально по SHA-256 (`data/cache/llm/`), а исходные прокси хранятся локально в течение `RETENTION_DAYS`.
3. **Режим `url-mode` с `video_metadata` (offsets):**
   - Передача публичной YouTube-ссылки напрямую в Gemini с таймкодами начала/конца (`start_offset` / `end_offset`) отключена по умолчанию (`URL_OFFSETS_OK=false`), пока не проведена платная калибровка на целевом аккаунте (`scripts/calibrate.py --live`). По умолчанию используется надёжный `file-mode` (локальная нарезка секций через `yt-dlp` + `ffmpeg` и загрузка в Files API).
4. **Блокировки контента фильтрами безопасности (Safety Filters):**
   - В игровых стримах (шутеры, хорроры) или эмоциональных разговорах с ненормативной лексикой отдельные 45-минутные куски могут быть заблокированы фильтрами безопасности модели.
   - Такие куски не роняют весь пайплайн: кусок помечается статусом `partial`, логируется причина, а обработка продолжается со следующего куска.
5. **Погрешность таймкодов на первом проходе (Pass 1 Scan):**
   - На низком разрешении (`MEDIA_RES_SCAN=low`, ~100 токенов/с) модель может ошибаться в границах момента на 1–3 секунды.
   - Ограничение компенсируется двухэтапным уточнением: **Pass 2 Refine** (`MEDIA_RES_REFINE=high` в окне `±30 с`) и **S5b Boundary Snapping** (привязка к паузам речи через `silencedetect` и сменам кадров в радиусе `±1.0 с`).

## 2. Видеоисточники и `yt-dlp`

1. **Закрытые и платные трансляции (Members-only / Sub-only):**
   - Стримы «только для спонсоров» на YouTube и платные архивы (Sub-only VOD) на Twitch требуют авторизационных cookies браузера. По соображениям безопасности передача пользовательских cookies по умолчанию отключена; такие видео следует сначала скачать локально и подать в ClipHunter как файл.
2. **Запись идущих стримов (`cliphunter live`):**
   - Сегментная запись живого потока (`-f segment -segment_time CHUNK_S`) зависит от стабильности HLS-потока площадки. При длительном обрыве интернет-соединения процесс FFmpeg завершит текущий сегмент и остановит сессию (уже записанные сегменты будут полностью обработаны пайплайном).
3. **Изменения вёрстки видеохостингов:**
   - YouTube и Twitch периодически меняют внутренние API отдачи потоков. При ошибках скачивания рекомендуется обновить `yt-dlp` внутри виртуального окружения: `uv lock --upgrade-package yt-dlp && uv sync`.

## 3. Экспорт черновиков в CapCut Desktop

1. **Привязка к версии CapCut Desktop (`9.6.0.4097`):**
   - Внутренний формат `draft_content.json` / `draft_info.json` не является публичным стандартом и может изменяться разработчиками CapCut в новых релизах (вплоть до шифрования файла проекта).
   - Экспортер протестирован и зафиксирован под **CapCut Desktop `9.6.0.4097` (Windows, схема `version: 360000`)**. Рекомендуется отключить автообновление CapCut Desktop.
2. **Абсолютные пути к медиафайлам:**
   - Схема черновика CapCut хранит абсолютный путь к `.mp4` файлу на диске. При переносе папки черновика на другой компьютер путь к видео изменится, и CapCut попросит указать файл заново (Relink media), если не включено копирование медиа внутрь папки черновика (`copy_media=True`).

## 4. Telegram-бот (`aiogram 3`)

1. **Лимит размера файла (50 МБ):**
   - Стандартный облачный сервер Telegram Bot API (`api.telegram.org`) ограничивает отправку видео ботом до **50 МБ** (`sendVideo`), а скачивание файлов, отправленных пользователем боту, — до **20 МБ** (`getFile`).
   - Если смонтированный клип превышает 50 МБ, бот не падает с ошибкой, а присылает текстовое уведомление с локальным путём к готовому файлу на сервере. Для снятия лимита до 2000 МБ можно развернуть локальный `telegram-bot-api` сервер.

## 5. Монтаж, FFmpeg и субтитры

1. **Опциональные субтитры (`SUBTITLES=true`):**
   - Генерация пословных караоке-субтитров `.ass` требует установленного пакета `faster-whisper` и скачивания весов модели Whisper. По умолчанию `SUBTITLES=false`. Если пакет не установлен, рендерер автоматически пропускает шаг субтитров без сбоя задачи.
2. **Аппаратное ускорение (`USE_NVENC=true`):**
   - Требует видеокарту NVIDIA и актуальный драйвер с поддержкой `h264_nvenc`. При `USE_NVENC=false` (по умолчанию) используется процессорный кодек `libx264` (`-crf 18 -preset medium`), работающий на любой машине.
3. **Макет `facecam_top_game_bottom_9x16`:**
   - Качество вертикальной склейки «вебкамера сверху + игра снизу» зависит от точности координат `facecam_rect` в профиле стримера. Если стример переместил камеру в другой угол экрана во время эфира, координаты в профиле нужно скорректировать через «⚙️ Профили» в веб-интерфейсе.

## 6. База данных и параллелизм

1. **SQLite по умолчанию:**
   - Для работы «из коробки» без Docker по умолчанию используется SQLite (`sqlite+aiosqlite:///data/cliphunter.db`). SQLite отлично подходит для одного пользователя (Web UI + CLI + бот на одной машине), но при высокой конкурентной записи с нескольких воркеров возможны блокировки (`database is locked`).
   - Для многопользовательской или серверной эксплуатации рекомендуется переключить `DATABASE_URL` в `.env` на PostgreSQL (`postgresql+psycopg://...` из `docker-compose.yml`).
