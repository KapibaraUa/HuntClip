## 1. Цель продукта

Приложение для нарезчика стримеров. Пользователь даёт ссылку на YouTube (запись стрима, VOD или готовая нарезка) либо файл. ИИ **смотрит видео и слушает звук**, находит лучшие моменты, приложение вырезает их, монтирует и отдаёт готовые клипы. Опционально создаёт черновики CapCut для ручной доводки.

**Жёсткое ограничение.** Моменты выбирает модель, которая смотрит само видео (кадры и аудио). Транскрипция, чат стрима, громкость и прочие эвристики не участвуют в выборе моментов. Разрешено: Whisper только для субтитров в готовом клипе (модуль монтажа, по умолчанию выключен); `silencedetect` и детектор сцен только для подгонки границ уже найденного момента.

## 2. Требования

Функциональные:

- F1. Принять публичную ссылку YouTube (watch, live, shorts, youtu.be), включая запись завершённого стрима.
- F2. Принять файл (mp4, mkv, mov, webm), включая готовые нарезки и компиляции.
- F3. Принять другие ссылки (Twitch VOD и т.п.) через yt-dlp, анализ в файловом режиме.
- F4. Найти кандидатов многопроходно: поиск, уточнение границ, финальный рейтинг (раздел 7).
- F5. Нарезать клипы с точными границами и без артефактов на стыках.
- F6. Смонтировать: кроп 9:16 или 16:9, шаблон, нормализация звука, опционально субтитры.
- F7. Ревью: список моментов, плеер, правка границ, отклонение, ручное добавление момента.
- F8. Экспорт: mp4 и `manifest.json`; опционально черновик CapCut.
- F9. Учёт токенов и стоимости на задачу, лимит бюджета, подтверждение дорогих задач.
- F10. Запись идущего стрима и анализ по мере записи (фаза 6).

Нефункциональные: локальный запуск (Docker Compose, опционально GPU); возобновляемость; воспроизводимость (версия промпта, модели и параметров сохраняется у каждого результата); тестируемость на эталонном наборе (раздел 13).

## 3. Режимы входа

| Вход | Режим анализа | Откуда нарезаем |
| --- | --- | --- |
| Публичный YouTube | url-mode (ссылка передаётся в Gemini) и параллельная загрузка yt-dlp | локальный файл |
| Непубличное, возрастное, members, Twitch, прочее | file-mode (скачать, сделать прокси, загрузить в Files API) | локальный файл |
| Загруженный файл | file-mode | тот же файл |

Правила:

- Если Gemini отклонил ссылку, автоматический откат на file-mode.
- Видео короче порога (по умолчанию 45 мин при обычном разрешении) анализируется одним запросом без разбиения.
- Известные факты (сверить): выборка 1 кадр в секунду; около 300 токенов в секунду видео при обычном разрешении и около 100 при низком; контекст около 1M токенов; URL-режим только для публичных видео; на платном тарифе нет лимита по длине YouTube-видео; до 10 видео в запросе; Files API до 20 ГБ на файл (платный тариф).
- Известная проблема: на форуме разработчиков сообщали, что при `start_offset` и `end_offset` для YouTube-ссылок аудио-токены считаются для всего видео. Измерь на калибровке (фаза 0) и выставь флаги `URL_OFFSETS_OK` и `URL_TS_RELATIVE_TO_WINDOW`. Если обрезка по ссылке дорогая, используй file-mode с нарезкой кусков самим.
- Агентный режим Gemini (модель сама листает таймлайн) на калибровке сравни со статическим. Он начинает с транскрипции, поэтому по умолчанию выключен: `AGENTIC_MODE=false`.

## 4. Архитектура

```
[Web UI / Telegram-бот / CLI]
          |
      [FastAPI]  --  [Postgres]  (jobs, sources, chunks, candidates, clips, api_calls)
          |
      [Redis + Dramatiq workers]
          |
 S0 ingest -> S1 download+proxy -> S2 chunk plan -> S3 scan (Gemini, pass 1)
 -> S4 merge/dedupe -> S5 refine (Gemini, pass 2) -> S6 judge (Gemini, pass 3)
 -> [ревью: человек] -> S7 cut (FFmpeg) -> S8 edit (FFmpeg) -> S9 export
          |
   [Storage: data/sources, data/proxies, data/chunks, data/clips, data/out]
```

Принципы: этапы это чистые функции над артефактами; один воркер выполняет одну задачу; тяжёлые вызовы (FFmpeg, yt-dlp) идут через subprocess с таймаутами; вызовы Gemini собраны в отдельном слое `llm/` с кэшем и учётом бюджета.

## 6. Модель данных

- `sources`: id, kind (youtube\_url, file, other\_url), url, path, duration\_s, title, channel, sha256, status.
- `jobs`: id, source\_id, profile\_id, params (JSON), stage, status, cost\_usd, budget\_usd, created\_at, error.
- `chunks`: id, job\_id, idx, start\_s, end\_s, file\_uri (Files API), status, tokens\_in, tokens\_out.
- `candidates`: id, job\_id, chunk\_id, start\_s, end\_s, category, score, status (raw, merged, refined, dropped, accepted, rejected, rendered), data (JSON с полями схемы), source\_pass (scan, refine, judge, manual), prompt\_version.
- `clips`: id, candidate\_id, path, layout, template, duration\_s, manifest (JSON).
- `api_calls`: id, job\_id, stage, model, mode, tokens\_in, tokens\_out, cost\_usd, latency\_ms, cache\_hit, error.
- `profiles`: name, language, game, facecam\_rect, gameplay\_rect, clip\_min\_s, clip\_max\_s, prompt\_addon, template, watermark.

Все времена хранить в секундах от начала исходного видео (float). Строки ММ:СС существуют только на границе с моделью.

## 7. Пайплайн по этапам

**S0. Ingest.** Определить тип входа, проверить доступность (yt-dlp `--simulate` или ffprobe), получить длительность, название, канал. Оценить стоимость (длительность, токены в секунду, цена) и показать пользователю; если выше `CONFIRM_ABOVE_USD`, ждать подтверждения.

**S1. Загрузка и прокси.** yt-dlp скачивает лучший формат в `data/sources/{id}`. FFmpeg делает прокси: 720p, 24 fps, CRF около 30, звук AAC около 96 кбит/с (Gemini всё равно берёт 1 кадр в секунду, а звук должен остаться чистым). В url-mode анализ стартует сразу, загрузка идёт параллельно.

**S2. План кусков.** Если видео не длиннее `SHORT_VIDEO_MAX_S`, один кусок. Иначе куски длиной `CHUNK_S` (по умолчанию 2700 с, то есть 45 мин) с перекрытием `OVERLAP_S` (120 с); шаг равен `CHUNK_S` минус `OVERLAP_S`. Проверка: `CHUNK_S` умноженное на токены в секунду при выбранном разрешении должно быть меньше 60% контекста.

**S3. Поиск (проход 1).** Для каждого куска: url-mode (ссылка и offsets) или file-mode (нарезать кусок из прокси, загрузить в Files API, дождаться статуса ACTIVE). Разрешение `media_resolution=low`. Системная инструкция `prompts/scan.md`, параметры из профиля, structured output. Ответ парсится в Pydantic, таймкоды переводятся в секунды и в глобальную шкалу (`global = chunk_start + local`). Ошибки: невалидный JSON, один повтор с текстом ошибки; блокировка по безопасности, кусок помечается partial; 429 и 5xx, повторы с экспоненциальной паузой. Кандидаты записываются со статусом raw.

**S4. Слияние и дедупликация.** Кандидаты из соседних кусков, пересекающиеся по времени не менее чем на 50% от более короткого, сливаются: остаётся тот, у кого score выше, evidence объединяется. Затем: клипы с длительностью вне допуска `[CLIP_MIN_S − tolerance, CLIP_MAX_S + tolerance]` помечаются для refine (не удаляются); ограничение числа кандидатов `MAX_CANDIDATES_PER_HOUR`; равномерное покрытие (не больше `MAX_PER_30MIN` из любого получасового отрезка при наличии альтернатив).

**S5. Уточнение (проход 2).** Для каждого кандидата окно `[start − PAD_BEFORE, end + PAD_AFTER]` (по умолчанию 30 с) вырезается из прокси и отправляется в обычном разрешении; для динамичных игр частота кадров выше 1 (сверить параметр fps). Промпт `prompts/refine.md`. Ответ: verdict (keep или drop), точные границы, что вырезать внутри, score. Границы переводятся в глобальную шкалу и подгоняются (S5b): сдвиг к ближайшей паузе звука (`silencedetect`) или смене сцены в пределах `SNAP_S` (1 с). Если после уточнения длительность вне допуска, один повтор, затем drop.

**S6. Финальный рейтинг (проход 3).** Сохранившиеся кандидаты нарезаются в черновые клипы (из прокси, без монтажа) и отправляются в Gemini пачками по `JUDGE_BATCH` (до 10 видео, сверить) с промптом `prompts/judge.md`. Ответ: score, keep или drop, причины, варианты заголовков. Итоговый порядок это сортировка по score.

**Ревью (человек).** Задача останавливается в статусе `awaiting_review`. UI показывает кандидатов; пользователь принимает, отклоняет, двигает границы (точность 0,1 с), добавляет момент вручную. Режим `AUTO_RENDER=true` пропускает ревью и рендерит всё принятое ИИ.

**S7. Нарезка.** Точная нарезка из оригинала (раздел 9), короткое затухание звука на краях.

**S8. Монтаж.** Выбранный layout и шаблон, нормализация звука, опционально субтитры.

**S9. Экспорт.** `out/{job}/{nn}_{slug}.mp4`, `manifest.json` на клип и на задачу, опционально черновик CapCut, журнал стоимости.

## 8. Работа с Gemini (слой `llm/`)

- **Клиент.** Класс `GeminiVideoClient` с методами `scan(chunk)`, `refine(window)`, `judge(clips)`. Все вызовы идут через единую функцию `call()`: проверка бюджета до вызова, учёт `usage_metadata` после, запись в `api_calls`, кэш.
- **Кэш.** Ключ: sha256 от (sha источника, start, end, модель, media\_resolution, fps, версия промпта, параметры профиля). Повторный запуск тех же данных ничего не стоит. Кэш хранит сырой ответ модели.
- **Бюджет.** `MAX_COST_USD_PER_JOB`. Перед вызовом оценка стоимости; при превышении задача уходит в `paused_budget`, пользователь может поднять лимит и продолжить.
- **Цены.** `PRICE_IN_PER_M` и `PRICE_OUT_PER_M` в конфиге, значения взять с актуальной страницы цен (сверить; возможны вводные цены с датой окончания). Токены «мышления» тарифицируются как выходные (сверить); уровень мышления вынести в конфиг и подобрать на калибровке.
- **Структурированный ответ.** Pydantic-модели из Приложения B → JSON schema → параметр схемы ответа в SDK. После ответа валидировать: формат времени, `start < end`, укладывание в границы куска, допустимые категории, диапазон score.
- **Таймкоды.** `parse_ts('MM:SS' | 'HH:MM:SS') -> float`. Значения вне границ куска: кандидат отбрасывается, событие логируется. Перевод в глобальную шкалу только в одном месте (`timecodes.py`), покрыт тестами.
- **Безопасность контента.** Игровые стримы содержат мат и насилие. При блокировке по безопасности пометить кусок `partial`, записать причину, не падать. Настройки безопасности вынести в конфиг (сверить допустимые значения).
- **Параллелизм.** Семафор `LLM_CONCURRENCY` (по умолчанию 2), учёт лимитов запросов и токенов в минуту (сверить для вашего тарифа). Повторы через tenacity с экспоненциальной паузой на 429 и 5xx.
- **Языки.** Описания и заголовки на языке профиля (по умолчанию русский), цитаты на языке оригинала.
- **Версионирование промптов.** В шапке каждого файла `prompts/*.md` строка `version: N`; версия пишется в `candidates.prompt_version` и в манифест клипа.
- **Калибровка (фаза 0), `scripts/calibrate.py`.** Измерить и записать в `docs/CALIBRATION.md`: (1) токены и стоимость url-mode с offsets и без на одном и том же 5-минутном окне; (2) относительно чего возвращаются таймкоды в url-mode; (3) токены file-mode на куске 10 минут при low и обычном разрешении; (4) разница качества low и обычного разрешения на 5 известных моментах; (5) статический и агентный режимы на одном куске; (6) влияние уровня мышления на качество и цену; (7) точность таймкодов (средняя ошибка в секундах относительно ручной разметки). По итогам обновить значения по умолчанию в конфиге.

## 9. Видео: нарезка и монтаж (FFmpeg)

Точная нарезка из оригинала (перекодирование, `-ss` перед `-i`):

```
ffmpeg -y -ss {start} -i {src} -t {dur} -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p -c:a aac -b:a 192k -af afade=t=in:st=0:d=0.1,afade=t=out:st={dur-0.15}:d=0.15 -movflags +faststart {out}
```

Для источников 60 fps сохранять fps (потолок 60). Флаг `USE_NVENC=true` переключает на `h264_nvenc` с эквивалентным качеством.

Layouts (`video/layouts.py`, каждый возвращает фильтр FFmpeg):

- `original`: без изменений (16:9).
- `center_crop_9x16`: `crop=ih*9/16:ih,scale=1080:1920`.
- `blur_fit_9x16`: исходник по центру на размытом фоне: `[0:v]split=2[bg][fg];[bg]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=30:5[b];[fg]scale=1080:-2[f];[b][f]overlay=(W-w)/2:(H-h)/2`
- `facecam_top_game_bottom_9x16`: вертикальная склейка двух областей, фейскам сверху, геймплей снизу. Области берутся из профиля стримера как доли кадра (`x, y, w, h` от 0 до 1), собираются через `crop` с выражениями от `iw` и `ih`, затем `scale` и `vstack`.
- Опционально в фазе 4: трекинг лица (MediaPipe) для динамического кропа.

Звук: `loudnorm=I=-16:TP=-1.5:LRA=11` (двухпроходный режим, если нужна точность).

Субтитры (модуль выключен по умолчанию, `SUBTITLES=false`): faster-whisper запускается на звуке уже готового короткого клипа, слова с таймкодами пишутся в `.ass` (стиль с построчной подсветкой), накладываются фильтром `ass=file.ass`. Это оформление, а не часть выбора моментов.

Оформление: логотип или водяной знак из профиля (`overlay`), заголовок в первые секунды (`drawtext` или `.ass`), шрифт и цвета из шаблона.

Проверка результата после рендера: `ffprobe`, длительность отличается от плана не более чем на 0,15 с, есть и видео, и аудио, размер файла больше нуля; результат пишется в манифест. Таймаут на рендер: `FFMPEG_TIMEOUT_S`. Ошибки FFmpeg логируются вместе со stderr.

## 10. Экспорт и CapCut

`manifest.json` клипа: id, источник (url или путь), `start_s`, `end_s`, категория, score, `title_options`, `visual_evidence`, `audio_evidence`, `why_viral`, модель, режим, версия промпта, layout, шаблон, дата.

CapCut-экспорт (фаза 5, `CAPCUT_EXPORT=false` по умолчанию):

- У CapCut нет официального API для монтажа. Модуль только создаёт файлы черновика через VectCutAPI (HTTP-сервис) или pyCapCut, интерфейс CapCut не автоматизируется. По одному из обзоров условия CapCut запрещают скриптовый доступ, поэтому владелец должен принять решение осознанно.
- Интерфейс `Exporter.export(clip) -> Path`. Для CapCut результат кладётся в `out/{job}/capcut_drafts/{clip_id}`; в README описать, как скопировать папку в каталог черновиков CapCut.
- Формат черновиков зависит от версии CapCut: зафиксировать проверенную версию в `docs/DECISIONS.md`, отключить автообновление, добавить smoke-тест на фикстуре и ручную проверку после каждого обновления.
- Содержимое черновика: видеоклип (исходник с обрезкой по границам или готовый клип), текст заголовка, при необходимости субтитры.

## 11. API, интерфейс и бот

Эндпоинты:

- `POST /api/uploads`: загрузка файла по частям (multipart или tus), возвращает `source_id`.
- `POST /api/jobs`: `{url | source_id, profile_id, params}`.
- `GET /api/jobs/{id}` и `GET /api/jobs/{id}/events` (SSE: этап, прогресс, стоимость).
- `GET /api/jobs/{id}/candidates`; `PATCH /api/candidates/{id}` (границы, статус); `POST /api/jobs/{id}/candidates` (ручной момент).
- `POST /api/jobs/{id}/render` (выбранные кандидаты, layout, шаблон).
- `POST /api/jobs/{id}/cancel` и `POST /api/jobs/{id}/retry-stage`.
- `GET /api/clips/{id}/download` и `GET /api/jobs/{id}/usage`.
- `GET` и `PUT /api/profiles`.

Экраны:

1. Новая задача: поле для ссылки или перетаскивание файла, выбор профиля, длительности клипов, лимит бюджета, оценка стоимости до запуска.
2. Ход задачи: этапы, прогресс, расход токенов, лог.
3. Ревью: видеоплеер (прокси), таймлайн с отметками кандидатов, список с оценкой и полями `why_viral`, `visual_evidence`, `audio_evidence`; ручки для границ; кнопки принять, отклонить, добавить момент; предпросмотр выбранного layout.
4. Результаты: сетка клипов, скачивание, копирование заголовков.
5. Настройки: профили стримеров (область фейскама и геймплея, длительности, дополнение к промпту, шаблон), модель и параметры, бюджет.

Telegram-бот (фаза 6): пользователь отправляет ссылку или файл, бот присылает оценку стоимости и просит подтвердить, шлёт статусы этапов, затем клипы (если файл слишком большой для Telegram, то ссылку на скачивание; актуальный лимит Bot API сверить). Доступ только для разрешённых `user_id`.

Запись идущего стрима (фаза 6): `yt-dlp --live-from-start` или streamlink пишет в сегменты; каждый завершённый сегмент длиной `CHUNK_S` отправляется в пайплайн; кандидаты появляются в ревью по мере записи.

## 12. Конфигурация и наблюдаемость

`.env.example` должен содержать: `GEMINI_API_KEY`, `GEMINI_MODEL`, `AGENTIC_MODE`, `MEDIA_RES_SCAN`, `MEDIA_RES_REFINE`, `REFINE_FPS`, `CHUNK_S`, `OVERLAP_S`, `SHORT_VIDEO_MAX_S`, `PAD_BEFORE_S`, `PAD_AFTER_S`, `SNAP_S`, `CLIP_MIN_S`, `CLIP_MAX_S`, `MAX_CANDIDATES_PER_HOUR`, `MAX_PER_30MIN`, `JUDGE_BATCH`, `LLM_CONCURRENCY`, `MAX_COST_USD_PER_JOB`, `CONFIRM_ABOVE_USD`, `PRICE_IN_PER_M`, `PRICE_OUT_PER_M`, `URL_OFFSETS_OK`, `URL_TS_RELATIVE_TO_WINDOW`, `AUTO_RENDER`, `SUBTITLES`, `CAPCUT_EXPORT`, `USE_NVENC`, `FFMPEG_TIMEOUT_S`, `DATA_DIR`, `RETENTION_DAYS`, `DATABASE_URL`, `REDIS_URL`, `TELEGRAM_TOKEN`, `TELEGRAM_ALLOWED_IDS`.

Логирование: структурированный JSON, поле `job_id` во всех записях, ключи и токены маскируются. Метрики на задачу: время каждого этапа, токены, стоимость, доля cache hit, число кандидатов на каждом этапе (воронка raw, merged, refined, accepted). Хранение: `RETENTION_DAYS` для очистки `data/sources` и `data/proxies`; файлы в Files API хранятся ограниченное время (сверить), на них нельзя опираться как на хранилище, при необходимости перезагружать.

## 13. Тестирование и оценка качества

- **Юнит-тесты:** `parse_ts` и перевод в глобальную шкалу; планирование кусков (границы, перекрытие, последний неполный кусок); слияние и дедупликация; валидация схемы; подгонка границ; построители команд FFmpeg (проверка строк команд без запуска); расчёт бюджета и оценки стоимости.
- **Интеграционные:** пайплайн с замоканным Gemini (фикстуры ответов, включая сломанный JSON, таймкоды вне куска, блокировку по безопасности, 429); FFmpeg на коротком тестовом видео (3 минуты, сгенерированное или лицензионно чистое): нарезка, layouts, проверки через ffprobe.
- **E2E (по флагу `RUN_LIVE=1`):** реальный вызов API на 3-минутном публичном видео; проверяется, что пайплайн доходит до mp4 и укладывается в бюджет.
- **Эталонный набор (`golden/`):** 3–5 ваших стримов; для каждого JSON с моментами, которые человек считает лучшими (`start_s`, `end_s`, примечание). `make eval` прогоняет пайплайн и считает: recall (доля эталонных моментов, найденных моделью с IoU не ниже 0,5), precision принятых ИИ (доля клипов, которые человек оставил), среднюю абсолютную ошибку границ в секундах, стоимость на час видео, время обработки. Результаты пишутся в `eval/reports/` с версией промпта и модели, чтобы сравнивать изменения.
- **Правило:** любое изменение промпта или параметров сначала прогоняется через `make eval`; регресс по recall или precision блокирует слияние.

## 14. Фазы разработки и критерии приёмки

**Фаза 0. Основа и калибровка (2–3 дня).** Скелет репозитория, конфиг, логирование, Docker Compose (Postgres, Redis), CI. `scripts/calibrate.py` и отчёт `docs/CALIBRATION.md`. Приёмка: отчёт содержит измеренные значения по пунктам 1–7 раздела 8; значения по умолчанию в `.env.example` обновлены; принято решение, включать ли url-mode с offsets.

**Фаза 1. MVP в командной строке (1–2 недели).** `cliphunter run <url|file>`: этапы S0–S4 и S7, один профиль, один проход поиска, нарезка без монтажа, журнал токенов. Приёмка: на 60-минутном публичном видео получено не менее 5 mp4 и `manifest.json`; стоимость и токены в отчёте; повторный запуск берёт всё из кэша и стоит 0; падение посреди работы продолжается с нужного этапа.

**Фаза 2. Качество (1–2 недели).** Проходы S5 и S6, подгонка границ, слияние, ограничения покрытия, бюджет, `make eval`, golden-набор. Приёмка: отчёт eval на 3 стримах; recall и precision зафиксированы как базовая линия; средняя ошибка границ после S5 лучше, чем после S3.

**Фаза 3. Сервис и ревью (1–2 недели).** БД, API, воркеры, веб-интерфейс (экраны 1–4 из раздела 11), SSE. Приёмка: полный цикл из браузера (ссылка, ревью с правкой границ, рендер, скачивание); ручной момент рендерится так же, как найденный ИИ.

**Фаза 4. Монтаж (1 неделя).** Layouts, профили стримеров с областями кадра, нормализация звука, шаблоны, водяной знак, опциональные субтитры. Приёмка: один и тот же момент рендерится во всех layouts; проверки через ffprobe проходят; владелец визуально проверил 3 клипа.

**Фаза 5. Экспорт в CapCut (3–5 дней, по решению владельца).** Приёмка: черновик открывается в зафиксированной версии CapCut, клип на таймлайне, заголовок на месте.

**Фаза 6. Удобства (по приоритету владельца).** Telegram-бот, запись идущих стримов, Twitch и другие источники, пакетная обработка очереди ссылок, редактирование профилей из интерфейса.

**Фаза 7. Полировка.** Документация, резервное копирование БД, ротация логов и данных, скрипт установки, список известных ограничений.

**Контрольная точка.** Фазы 0–2 отвечают на главный вопрос: находит ли ИИ те моменты, которые выбрали бы вы. Если после настройки промпта recall на golden-наборе ниже 0,5, остановиться и обсудить с владельцем до начала фазы 3.

Ты — продюсер и монтажёр клипов по стримам (YouTube Shorts, TikTok, Reels и нарезки для YouTube). Ты СМОТРИШЬ видео и СЛУШАЕШЬ звук. Все выводы делай по тому, что реально видно на экране и слышно, а не по догадкам.

ТРЕБОВАНИЯ К КЛИПУ
- Самодостаточность: зритель понимает, что происходит, без остального стрима. В начало входит короткая завязка (что вообще происходит), без воды.

## Приложение B. Схемы ответов (Pydantic)

Если SDK принимает только подмножество JSON Schema, упростить схемы (например, заменить `str | None` на пустую строку) и сверить поддерживаемые возможности в документации.

```python
from typing import Literal
from pydantic import BaseModel, Field

Category = Literal[
    "emotion", "game_moment", "story", "funny", "opinion", "fact_advice", "conflict", "quote"
]


class CutRange(BaseModel):
    start: str  # MM:SS
    end: str


class ScanClip(BaseModel):
    start: str = Field(description="MM:SS или HH:MM:SS от начала переданного фрагмента")
    end: str
    confidence_timestamps: Literal["high", "medium", "low"]
    category: Category
    working_title: str
    hook_text: str | None
    visual_hook: str
    what_happens: str
    visual_evidence: str
    audio_evidence: str
    why_viral: str
    ending_text: str | None
    cuttable_inside: list[CutRange] = []
    title_options: list[str]
    score: int = Field(ge=1, le=10)
    risks: list[str] = []


class ScanResponse(BaseModel):
    notes: str | None
    clips: list[ScanClip]


class RefineResponse(BaseModel):
    verdict: Literal["keep", "drop"]
    start: str | None
    end: str | None
    cut_inside: list[CutRange] = []
    score: int = Field(ge=1, le=10)
    reason: str


class JudgeItem(BaseModel):
    clip_index: int = Field(ge=1)
    verdict: Literal["keep", "drop"]
    score: int = Field(ge=1, le=10)
    hook: int = Field(ge=1, le=10)
    emotion: int = Field(ge=1, le=10)
    completeness: int = Field(ge=1, le=10)
    standalone: int = Field(ge=1, le=10)
    reason: str
    title_options: list[str]


class JudgeResponse(BaseModel):
    items: list[JudgeItem]
```

Длительность клипа в схему не входит: её считает и проверяет код (разделы 7 и 8).
